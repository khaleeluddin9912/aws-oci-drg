# OCI DRG ↔ AWS VGW Site-to-Site VPN — Manual Console Runbook

This is the clean, verified sequence for building an IPsec VPN between an OCI VCN (via DRG)
and an AWS VPC (via VGW), with one VM on each side to test connectivity with `ping`.

Every ⚠️ marks a step that caused a real failure in a previous run-through — pay close
attention to those.

**Network plan:**

| | AWS | OCI |
|---|---|---|
| Region | ap-south-2 (or your choice) | ap-hyderabad-1 (or your choice) |
| CIDR | `10.10.0.0/16` | `10.20.0.0/16` |
| Subnet | `10.10.1.0/24` | `10.20.1.0/24` |
| Gateway | VGW | DRG |

---

## PART A — AWS Console Steps

### A1. VPC
- VPC → Create VPC → **VPC only**
- Name: `aws-oci-vpc`, IPv4 CIDR: `10.10.0.0/16`

### A2. Subnet
- Subnets → Create subnet
- VPC: `aws-oci-vpc`, Name: `aws-oci-public`, CIDR: `10.10.1.0/24`
- After creation → Edit subnet settings → enable **Auto-assign public IPv4**

### A3. Internet Gateway
- Internet Gateways → Create → name `aws-oci-igw`
- Attach to `aws-oci-vpc`

### A4. Route Table
- Route Tables → Create → name `aws-oci-rt`, VPC: `aws-oci-vpc`
- Add route: `0.0.0.0/0` → target = `aws-oci-igw`
- Subnet associations tab → associate `aws-oci-public`

### A5. Security Group
- Security Groups → Create
- Name: `aws-oci-vm-sg`, VPC: `aws-oci-vpc`
- Inbound: SSH (22) from your IP; ICMP (All) from `10.20.0.0/16`
- Outbound: leave default (all allowed)

### A6. Virtual Private Gateway
- Virtual Private Gateways → Create → name `aws-oci-vgw`, Amazon default ASN
- Select it → Actions → **Attach to VPC** → `aws-oci-vpc`
- Route Tables → `aws-oci-rt` → **Route Propagation** tab → enable for `aws-oci-vgw`

### A7. Temporary Customer Gateway
- Customer Gateways → Create
- Name: `oci-cgw-temp`, BGP ASN: `65000`, IP: `1.1.1.1`, Static routing
- (This placeholder exists because AWS needs a Customer Gateway to create the VPN
  connection, but we don't have OCI's real tunnel IP yet.)

### A8. VPN Connection
- Site-to-Site VPN Connections → Create
- Name: `aws-to-oci-vpn`
- Target: Virtual private gateway → `aws-oci-vgw`
- Customer gateway: Existing → `oci-cgw-temp`
- Routing: **Static**, Static IP prefix: `10.20.0.0/16`

**Tunnel 1 options → Edit tunnel 1 options:**
- Pre-shared key: set a 24–32 char alphanumeric string manually, write it down
  (⚠️ don't leave AWS to auto-generate — it may use `.` or `_`, which OCI rejects)
- IKE version: **ikev2 only**
- Phase 1 encryption: **AES256** only
- Phase 1 integrity: **SHA2-256** only
- Phase 1 DH group: **14** only ⚠️ (must match OCI exactly or IKE fails with "No Proposal Chosen")
- Phase 2 encryption: **AES256** only
- Phase 2 integrity: **SHA2-256** only
- Phase 2 DH group: **14** only ⚠️
- Phase 1 lifetime: `28800`, Phase 2 lifetime: `3600`
- Startup action: **Start**

Tunnel 2: leave all defaults, ignore — this lab only wires up tunnel 1.

- Create → wait for **Available**
- Go to **Tunnel details** tab → note **Tunnel 1 Outside IP** = `AWS_IP`

## PART B — OCI Console Steps

### B1. VCN
- Networking → VCN → **Create VCN Only**
- Name: `oci-aws-vcn`, CIDR: `10.20.0.0/16`

### B2. Internet Gateway
- Inside VCN → Internet Gateways → Create → `oci-aws-igw`

### B3. Security List
- Inside VCN → Security Lists → Create
- Name: `oci-aws-sl`
- Ingress: TCP/22 from your IP; ICMP/All from `10.10.0.0/16`
- Egress: default `0.0.0.0/0` all

### B4. Route Table (VCN's subnet route table)
- Inside VCN → Route Tables → Create
- Name: `oci-aws-rt`
- Rule 1: `0.0.0.0/0` → Internet Gateway → `oci-aws-igw`
- Rule 2 (add after DRG exists in B6): `10.10.0.0/16` → DRG → `oci-aws-drg`

### B5. Subnet
- Inside VCN → Subnets → Create
- Name: `oci-aws-public`, CIDR: `10.20.1.0/24`
- Route table: `oci-aws-rt`, Security list: `oci-aws-sl`, Public subnet

### B6. DRG
- Networking → Dynamic Routing Gateways → Create → `oci-aws-drg`
- DRG Attachments tab → Create DRG Attachment
  - Type: VCN, VCN: `oci-aws-vcn`
  - **DRG route table: leave as the default** —
    `Autogenerated Drg Route Table for VCN attachments` ⚠️
    Do NOT point this at a custom route table. OCI auto-imports routes between
    attachments only when each attachment stays on its own default DRG route table.
- Go back to B4 and add the missing `10.10.0.0/16 → oci-aws-drg` rule now that the DRG exists

### B7. CPE
- Networking → Customer-Premises Equipment → Create
- Name: `aws-cpe`, IP address: `AWS_IP` (from A8), Vendor: Other (or Oracle if listed)

### B8. IPSec Connection
- Networking → Site-to-Site VPN → IPSec Connections → Create
- Name: `oci-to-aws-vpn`, CPE: `aws-cpe`, DRG: `oci-aws-drg`
- Routing type: **Static**, Static route: `10.10.0.0/16`

**Tunnel 1:**
- Name: `tunnel-1-aws`
- Shared secret: leave OFF (let Oracle auto-generate) — simpler than typing a matching
  secret blind; you'll copy the generated value to AWS afterward
- IKE version: **V2**
- Routing: **Static**
- Leave the IPv4 inside tunnel interface fields **completely blank** ⚠️ (any stray
  character here causes a silent "Invalid CIDR" validation failure)

Tunnel 2: leave defaults.

- Create

### B9. Edit Tunnel 1 — lock in matching crypto
- Open `tunnel-1-aws` → Edit
- **Phase one (ISAKMP):** Set custom configurations ON
  - Encryption: AES_256_CBC, Auth: SHA2_256, **DH group: GROUP14** ⚠️, Lifetime: 28800
- **Phase two (IPSec):** Set custom configurations ON
  - Encryption: **AES_256_CBC** (not the default AES_256_GCM) ⚠️
  - Auth: HMAC_SHA2_256_128
  - PFS: ON, **DH group: GROUP14** ⚠️ (default was GROUP5 — must match AWS's Phase 2 DH group 14)
  - Lifetime: 3600
- Save (confirm the success notification actually appears)
- Click **View shared secret** → copy the value → this is your final PSK

### B10. Check the IPSec tunnel's DRG route table
- DRG → `oci-aws-drg` → IPSec tunnel attachments → `tunnel-1-aws`
- Confirm DRG route table = `Autogenerated Drg Route Table for RPC, VC, and IPSec
  attachments` ⚠️ (the other genuine default — leave it, don't reassign it)

---

## PART C — Close the loop back on AWS

### C1. Real Customer Gateway
- Customer Gateways → Create
- Name: `oci-cgw-real`, ASN `65000`, IP = OCI's tunnel VPN IP
  (find it: IPSec Connection page → tunnel list → **Oracle VPN IP address** column,
  on the row for `tunnel-1-aws` specifically — there are two tunnels listed, don't
  grab the wrong one)

### C2. Retarget the VPN connection
- `aws-to-oci-vpn` → Actions → **Modify VPN connection**
- Target type: Customer gateway → select `oci-cgw-real`
- Save
- ⚠️ Verify afterward: go to the Details tab and confirm **Customer gateway address**
  actually changed to OCI's IP. The modify screen has separate sections for
  "VPN gateway" vs "Customer gateway" targets — make sure you changed the right one.

### C3. Sync the PSK
- `aws-to-oci-vpn` → Actions → **Modify VPN tunnel options** → Tunnel 1
- Pre-shared key = the value copied from B9
- Save

### C4. Verify
- Wait 3–5 min → Tunnel details → Tunnel 1 = **Up**
- OCI → `tunnel-1-aws` → IPSec status = **Up**, ESP established = **Yes**

If it stays down, enable **Tunnel logging** on the AWS VPN connection (Modify VPN
tunnel options → Tunnel logging → point it at a CloudWatch log group) and read the
log stream — it will show you exactly which phase fails and why (e.g. "No Proposal
Chosen" with a DH group mismatch spelled out).

## PART D — VMs and connectivity test

### D1. AWS VM
- EC2 → Launch instance → Ubuntu, t3.micro
- **VPC: `aws-oci-vpc`, Subnet: `aws-oci-public`** ⚠️ (don't let it default to the
  account's default VPC — check the Networking tab after launch; a `172.31.x.x`
  private IP means it landed in the wrong VPC)
- Auto-assign public IP: ON
- Security group: `aws-oci-vm-sg`

### D2. OCI VM
- Compute → Create Instance → Oracle Linux, VM.Standard.E2.1.Micro (Always Free shape)
- VCN: `oci-aws-vcn`, Subnet: `oci-aws-public`, assign public IP
- Add your SSH public key

### D3. Disable/adjust firewalld on the OCI VM ⚠️
Oracle Linux ships with `firewalld` active by default, which blocks ICMP even when
OCI's security list allows it.

Quick test (not for production):
```bash
sudo systemctl stop firewalld
```

Proper fix (keeps the firewall on, allows ICMP):
```bash
sudo firewall-cmd --permanent --add-icmp-block-inversion
sudo firewall-cmd --reload
```

### D4. Ping test
```bash
# From the AWS VM
ping -c 4 <OCI_VM_PRIVATE_IP>

# From the OCI VM
ping -c 4 <AWS_VM_PRIVATE_IP>
```

Both directions should get replies once the tunnel is Up and firewalld is handled.

## Cleanup

**OCI (delete in this order):**
1. Compute → Instances → terminate the VM (delete boot volume too)
2. IPSec Connections → terminate `oci-to-aws-vpn`
3. Customer-Premises Equipment → delete `aws-cpe`
4. DRG → detach the VCN attachment, then delete `oci-aws-drg`
5. VCN → delete subnet, internet gateway, route table, security list, then the VCN

**AWS (delete in this order):**
1. EC2 → terminate the instance
2. VPN Connections → delete `aws-to-oci-vpn`
3. Customer Gateways → delete both (`oci-cgw-temp` and `oci-cgw-real`)
4. Virtual Private Gateways → detach from VPC, then delete `aws-oci-vgw`
5. Internet Gateways → detach, then delete `aws-oci-igw`
6. Route Tables → delete `aws-oci-rt`
7. Subnets → delete `aws-oci-public`
8. VPCs → delete `aws-oci-vpc`
9. CloudWatch → delete the tunnel log group if you created one

## Root causes of every failure hit while building this

| Symptom | Cause | Fix |
|---|---|---|
| Tunnel stuck Down, "IKE SA not established" | AWS still targeting placeholder `1.1.1.1` Customer Gateway | Actually complete the "Modify VPN connection" target change, verify on the Details tab |
| "No Proposal Chosen" / "No Proposal Match Found" in CloudWatch, DH Group 20 vs 14 | OCI Phase 1 custom config wasn't set (or reverted to default GROUP20) | Set Phase 1 custom DH group to GROUP14 on OCI, matching AWS |
| Phase 1 up, Phase 2 ("ESP established") stays No | OCI Phase 2 defaulted to AES_256_GCM / GROUP5 instead of matching AWS's AES256/DH14 | Set Phase 2 custom encryption to AES_256_CBC and DH group to GROUP14 |
| Tunnel shows Up on both sides, but 100% ping loss | AWS VM launched into the account's **default VPC**, not the VPN-connected VPC | Relaunch the VM explicitly into `aws-oci-vpc` / `aws-oci-public` |
| Still 100% ping loss after fixing the VPC | OCI VCN attachment was pointed at a **custom** DRG route table instead of the true default, breaking OCI's automatic route import between the VCN and IPSec attachments | Set the VCN attachment's DRG route table back to `Autogenerated Drg Route Table for VCN attachments`; leave the IPSec attachment on its own autogenerated table; add no manual static routes |
| Still no ping after routing was fixed | `firewalld` active on Oracle Linux blocking ICMP at the OS level | `sudo systemctl stop firewalld` (test) or allow ICMP properly with `firewall-cmd` |
